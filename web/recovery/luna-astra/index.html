How to read the comparison

Low, medium, high and xhigh are requested reasoning-effort settings. A model named “fast” is not guaranteed to respond faster. Every call starts a fresh Codex session, so latency includes startup, prompt overhead and provider queueing. Two trials share this Mac concurrently. Treat timings as measurements of this setup.

Pure Luna uses a fixed task plan; pure Astra generates a plan and makes decisions at the same selected effort. All groups share perception, guards, observation budgets and robot skills. Planning and decision effects should therefore be interpreted separately.

WHAT THIS EXPERIMENT ESTABLISHES

A bounded test of the model gate.

Shared execution

Calibrated RGB-D becomes a small observation summary. A guard validates the model decision. Once the target is visible, the same frozen stacking skill runs in every group.

Fast / slow workflow

Astra creates a conditional plan. Luna selects continue, reobserve, escalate or stop. An escalation can invoke an Astra revision, but any revised plan requires fresh evidence before motion.

Independent outcomes

A private simulator evaluator checks the completed tower. Persistent occlusion requires no robot movement and an explicit guarded stop. Simulator object truth is never an actor input.

What is still missing

Model decisions during grasp and placement, successful online manipulation repair, large heldout evaluations, calibrated confidence and real-robot evidence are future work.

Do not confuse a repair call with recovery.

“Slow repairs” counts actual replanning calls. A revision followed by a stop does not establish a successful recovery. The current gate acts before manipulation; existing retries inside the frozen robot skill are not new model learning.
