# 从几何表示到可恢复的机器人 agent

2026-09-24；本地讨论稿。用户优先级：滑落/遮挡后的重新规划；界面同时支持演示和研究细节。本轮不改 Notion、不创建分支、不提交或推送代码。

## 结论与建议

建议研究主线为：**带来源与不确定性的几何状态，能否让 agent 在失误后更好地选择重观测、重抓、局部重建，以及何时调用强 LLM？**

几何表示是接口，恢复选择是待改进策略，修复记忆是跨试验积累的结果。先用相同预算下的失败恢复比较建立证据，再扩展到桥、双塔与交替施工。不要同时把“更好感知、更多重试、更大 LLM、更多候选”全改掉后将收益归因于其中一项。

### 需要澄清的研究表述

1. B 提到已知积木和夹爪几何。已知物体模板属于可声明先验；**当前物体真实位置、姿态、接触**才是禁止泄漏的在线真值。两者不要混称。现有 inventory 策略从 RGB-D 测尺寸；应把“已知模板拟合”和“未知尺寸估计”作为两种独立协议。
2. B 中约 20%→99% 是有价值的动机，但当前代码历史同时改了抓取、夹爪几何、搬底座、落位预测、重试和测试集合；不能由此单独断言几何表示造成了全部提升。需在相同 seed、控制器、预算下比较。
3. B 的 `supported_by` 应写成“视觉支持假设”，不是接触传感器真值。遮挡时应该为 unknown；确定性布尔值会给 agent 虚假确定感。
4. “GPU-free”应限定到几何与策略计算。MuJoCo 图像渲染仍使用图形硬件/平台后端；远端 LLM 的推理硬件并不由此变成 CPU-only。
5. 文中 Jev 只是拟议的快速决策模型。本轮未验证其可用接口、延迟与效果；先使用确定性路由器作为可测基线，之后可替换预训练模型，保持预算一致。
6. A 列过四面体、半球、拱桥等早期形状；当前 `block_catalog.py` 的 20 物体库只有 cube、thin_prism、prism、cylinder、triangular_prism。新任务从当前可用形状出发。
7. 2D 绘图必须含深度/高度或模板约束，才能形成无歧义的 3D 目标。目标图需通过库存、支撑、碰撞和可达性预检；不可能任务应标记不可行，不能让策略无限修复。

## 可以引入 learning 的位置

| 层 | 现在是什么 | 无训练权重的 learning 方式 | 优先级/证据 |
|---|---|---|---|
| 几何与置信度 | 手写颜色阈值、点云拟合、形状分数、实例匹配 | LLM 修复拟合/关联程序；用开发集选择阈值；保留遮挡反例 | 高；但阈值选择仍是统计拟合，须冻结再测 |
| 主动观测 | 固定相机；部分 perceive 有重试 | 学何时等待、何时移动腕部换视角、何时放下 payload 再看 | 最高；先验证不移动的重观测，再加可达视点 |
| 抓取与落位 | 几何 servo、固定容差、两次尝试 | 改抓取高度/退让方向/落位补偿；按失败类型检索修复 | 高；当前已有有限恢复，须超越这一强基线 |
| 失败诊断 | 字符串日志 + 最终成功/失败 | 从时序视觉证据区分抓空、搬运丢失、支持偏移、感知失真 | 最高；不要把所有异常都当成抓取失败 |
| 恢复计划 | 单条 stack 顺序与局部重试 | 生成带前后置条件的 recovery DAG；只重建受损子结构 | 下一步核心；完整图执行器尚未连接 |
| 快慢路由 | 尚无统一运行时路由 | 基于不确定性/失败次数/风险检索规则；疑难时调用当前 LLM | 高；测漏报、误报、调用率、等待成本 |
| 修复记忆 | 历史学习技能、当前独立冻结策略 | 存适用范围、反例、代码 hash、回归结果；不只存成功话术 | 高；先无记忆基线，再测跨任务迁移 |
| 任务课程 | 手工固定任务 | agent 提议新困难，独立判别可行性；固定评测任务不被改写 | 中；防止 proposer 只生成容易任务 |
| 目标解释 | 硬编码蓝红绿/红细长柱目标 | 将自然语言/2D 模板编译为支撑 DAG 与容差，交给人预览 | 中；不能把自然语言输出直接变成电机命令 |

不建议本阶段把伺服实时环交给大 LLM，也不建议先做端到端 RL 或感知网络训练。这两条会改变两篇文档的 training-free 假设和比较对象。

## 我作为 LLM 具体做什么

- episode 前：把目标编译成计划，检查假设，挑一个可检验修复。
- episode 中：只在停稳且取得新观测后接收几何摘要/局部 RGB-D；返回有版本与有效期的结构化动作建议。由执行器再次检查，不直接输出连续关节轨迹。
- episode 后：阅读本轮开发证据、提出代码修改；在独立候选中运行同一回归集；失败修复也保存。
- promotion：冻结源码、数据协议、预算与 memory snapshot 后再预留评测。

本轮我已亲自做了两版小修复：v1 在初始三种任务颜色不完整时最多两次重观测，但被蓝色背景误导；v2 加入基于观测桌面平面的高度过滤，再判断颜色证据。持续遮挡仍停止。两版都是 code-as-policy 修复，不是完整在线 LLM agent，也不是从零学习。

## 现有证据边界

前面三组历史实验使用 privileged state，不能与纯视觉系列合并统计。当前视觉策略可用机器人模型和相机标定，私有评估器读取真值判分，但结果不返回执行中的策略。当前生成的符号层还不是统一 belief API：实例跟踪、cube 拟合与策略逻辑分散在模块中；新 harness 的数据契约和快慢路由是本轮提出并做离线测试的原型。

建议最小论文问题：**相同 rollout 与 LLM 预算下，带不确定性和适用条件的恢复记忆，是否比固定重试/无记忆 LLM 修复更好地处理未见遮挡与滑落？** 同时测表示尺寸、token、延迟以及恢复成功，避免只优化其中一个指标。
