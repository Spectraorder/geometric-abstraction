# Harness：可执行原型与正式评测设计

## 本轮已经落地

- `harness/run_fault_trial.py`：复用主线 runner 的 RPC、隔离 worker、物理模拟和原评估器，仅在副本中插入故障钩子。主线源码未修改。源码片段不匹配时拒绝执行；每次记录上游和 adapter hash。
- `policies/reobserve_then_stack_v2.py`：当前助手生成的一次初始重观测修复，来自冻结视觉策略；`provenance_v2.json` 保存假设、父策略和候选 hash。
- `harness/render_fault_trial.py`：实际物理状态回放；侧面面板显示策略收到的最近一张真实保存输入（包括遮挡），腕部面板重建用于观看。
- `harness/contracts.py`：belief 验证、简单快路径路由、带版本/时效的动作校验、开发集 memory promotion gate。**它是可运行的接口设计原型，尚未接入 MuJoCo 运行时，也没有实测在线 LLM 延迟。**
- `harness/test_contracts.py`：14 个对抗契约检查，覆盖过期动作、ID 歧义、缺失支撑、重复 ID、非数值不确定性、嵌套 oracle 字段、预留证据混入 memory 等。

字段黑名单不是完整的信息流安全证明。正式连接感知器时必须采用白名单序列化、独立进程和可审计数据来源；不能允许任意额外数值字段承载真值。当前已有策略仍在原 OS sandbox 中执行；实验故障表只在宿主端，执行策略看不到故障事件和未来时序。

## 故障语义

| 故障 | 触发 | 改动 | 不应宣称什么 |
|---|---|---|---|
| occlusion | 前两次策略侧面相机调用 | 用 RGB-D 桌面上方的蓝色区域包围盒扩 4 px 覆盖 RGB/深度有效性 | 图像空间遮挡代理，不是真实遮挡物碰撞/光学渲染 |
| persistent_occlusion | 每次侧面相机调用 | 同上，持续 | 停止是合理拒绝，不算堆塔任务成功 |
| miss | 第一次负角度闭合命令 | 应用开爪 0.8；保留原请求与应用值 | 执行器故障，不是感知噪声 |
| slip | 首次闭合后机器人升高 35 mm | 夹爪打开 0.45 s 后恢复 | 抬升开爪扰动，不是经过标定的摩擦滑落模型 |
| none | 无 | 原物理系统 | 与历史不同主机的大样本结果不能直接合并 |

注入器没有移动物体位姿。它只改变传感器像素或执行器命令，物体运动由物理模拟产生。slip 是否真的造成物体掉落须在私有诊断/录像中验证，不能只因触发了开爪就自动记为“滑落已发生”。

## 运行方法

从仓库根目录运行，`--output` 必须不存在：

```bash
uv run python -m unittest discover -s research/recovery_lab_20260924/harness -p 'test_*.py'
uv run python research/recovery_lab_20260924/harness/run_fault_trial.py \
  --fault occlusion --seed 4001 \
  --candidate research/recovery_lab_20260924/policies/reobserve_then_stack_v2.py \
  --output outputs/my_recovery_trial
uv run python research/recovery_lab_20260924/harness/render_fault_trial.py \
  --trial outputs/my_recovery_trial --speed 2 --fps 20
```

每次产生：`result.json`、实际 RPC、传感器帧、私有故障表、物理状态、视频和策略 hash。`fault_events.private.json` 只能给评估/离线分析，不可作为在线 agent 输入。原始结果和失败均保留，不覆盖、不删除。完整结果见 `docs/04_LOCAL_RESULTS.zh-CN.md`。

## 建议的正式接口

belief 的每个对象至少包含：实例 ID、颜色/形状候选、observed/fitted/propagated 来源、frame IDs、timestamp、可见面、几何估计与不确定区间、关联歧义、候选 grasp、视觉支撑假设及证据。隐藏顶点必须标记推断；模型分数不能直接称校准概率。

静态模板元数据单独存储，不与动态视觉观测混淆。机器人状态来源标记 proprioception。观测窗口、相机选择、原始图像补取次数都计入成本。

状态机：observe → validate → act_once → verify → continue/reobserve/retry/escalate/stop。每个动作有前置条件、后置条件、耗时和次数上限。动作/整个 trial 超时归类为基础设施问题或策略问题，不能随意剔除。

慢 LLM 提案有 belief_version、有效期、证据 ID 和允许的动作枚举。返回任意可执行代码不应在持物中的 episode 热替换；代码修改在下一条独立 trial 中运行回归。本轮候选就是后一种 offline 修复。

## 对照和消融

先固定场景、控制器、故障、最大动作次数、LLM 型号与预算，再比较：

| 组 | 信息/机制 | 想回答的问题 |
|---|---|---|
| B0 | 当前冻结策略＋已有重试 | 现有强基线已能恢复多少？ |
| B1 | B0＋固定重观测规则 | 简单规则是否足够？本轮做了小样本 |
| B2 | 几何摘要＋LLM，无 repair memory | 更强推理是否带来额外收益？ |
| B3 | B2＋条件化修复记忆与反例 | 跨失败类别复用是否有贡献？ |
| A1 | B3 去掉不确定性/时效 | 代价是误动作还是额外停止？ |
| A2 | B3 去掉回归 promotion | 记忆污染与旧任务退化多少？ |
| A3 | RGB-D 原图对比中心点/完整几何/自适应混合 | 最小表示在成功与成本之间如何取舍？ |
| Oracle diagnostic | 私有真值状态 | 分离感知瓶颈与执行瓶颈；只能单列 |

公平比较不能给 B3 更多重试次数、不同视觉输入或更容易的故障。同一场景和可复现故障配对，随机运行顺序；模型重复调用带随机性，至少多个独立 learning run，报告全部预算。

## 场景、切分与记忆冻结

本轮 4001/4002 都是开发/演示 seed，不是新预留集。正式协议建议：新建 versioned scene manifest，开发集合与本轮样例、历史全部公开 seed 标记为已见；例如候选预留范围 16001–16050 必须先核对没有被之前试验使用，再由独立 runner 封存。

更关键的是按**故障机制/时刻/幅度/物体组合**拆分，而不只是换 seed。比如开发只见起始遮挡，测试新增持物时遮挡；必须记录这是机制 OOD，不能混成同分布成功率。建议分层：短时遮挡、长时遮挡、抓空、抬升丢失、支撑偏移、同色身份歧义，每层先 20 个配对场景作 pilot，再做功效/置信区间评估。

冻结内容：策略 hash、harness hash、环境/传感器版本、分布 manifest、LLM prompt/model、memory snapshot、预算和停止规则。预留结果只进入只读报告。若看过失败并修复，则旧集合转开发，另建预留集。

## 指标与成功判定

- 原任务成功：最终结构判分；恢复成功：故障实际触发且确认后，仍完成原目标。故障没触发单列，不作为恢复成功。
- 可恢复子集成功与正确拒绝分别报告；持续遮挡停止不能算完成任务，也不应被当成 unsafe action。
- 时间：故障发生→检测→第一恢复动作→回归计划的模拟时间；wall time、LLM等待与控制暂停另列。
- 安全/稳定：每一步支撑检查、跌落次数、其他已完成子结构被破坏次数、真实机器人需额外规范。本轮只仿真。
- 效率：额外动作、额外观测、重新拆装数量、LLM调用/token、总rollout数；包括失败候选和回归。
- 快慢路由：不必要升级率、漏升级率、过期回复拒绝数、人工介入率。基于独立标注/私有离线标签判定，标签不返回 actor。
- 表示：序列化字节/token、估计误差、ID切换率、置信区间覆盖、未知率；不能只比压缩率。
- 报告配对结果与二项置信区间；样本只有 1–2 时仅报告原始计数，不宣称可靠性提升。

5 秒结构稳定窗是有限时域验证，不是任意未来扰动下稳定。总 COM 在支撑域内也是必要近似条件，不是摩擦、碰撞、动态稳定性的完备证明。
