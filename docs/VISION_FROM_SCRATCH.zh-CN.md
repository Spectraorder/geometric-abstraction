## 2. 模型实际如何学习

每轮启动一个新的 **gpt-6-astra Codex CLI 上下文**，输出完整 Python 策略。第 1 轮只给任务/API 说明和初始 RGB 图，没有加载仓库已有策略、任务技能库、用户历史或本对话。第 2 轮只加本次第 1 轮代码、传感器画面、策略自己记录的感知/决策及运行结束后的成功/失败反馈。根助手没有手工修改生成的两份候选策略。

第一轮根据颜色分割和深度反投影估算物体位置。红块遮住蓝块顶部后，重新估计的蓝块中心偏移，策略的视觉检查停止了后续动作。第二轮模型提出并实现两项修复：保留无遮挡时的底座位置；接近放置点时重新观察被夹物体，逐步修正偏移。红块稳定性也由两次相机观测比较，而不是查询模拟器判定。

**这里“从零”是任务策略/技能库为空，不是从随机模型权重训练。** 模型有预训练知识；任务顺序、RGB-D 几何约定、硬件限位与夹爪开合范围由任务说明提供。基础设施还提供通用 `move_tool`：根据已知机器人模型求解 IK，并带向下夹持的软姿态偏好。该 SDK 不读取物体状态，但本实验没有从零学习机器人运动学或底层关节控制。学习发生在代码策略修复层，没有更新神经网络权重。

两轮完整 `prompt.txt`、`invocation.json`、`model.jsonl`、`response.json`、`candidate.py` 都保存于各自轮次目录。两次正式模型调用均没有工具调用。隔离调试时另有一次在策略执行前终止的上下文探测，保存在 `infrastructure/rejected_actor_context`，没有用于正式候选。

## 3. 视觉输入和真值隔离

1. 模型提案：临时工作目录、独立临时 `CODEX_HOME`，仅复制已有登录凭据；禁用用户配置、宿主技能发现、shell、浏览器、apps 等。实际调用事件同时接受审计。
2. 策略执行：独立 Python 子进程通过 JSON RPC 获得传感器数据和机器人本体感知。MuJoCo 留在父进程，子进程没有 simulator 对象。
3. 策略源代码：限制数值库导入，禁止直接文件读取、动态导入、私有属性和常见反射入口；macOS `sandbox-exec` 禁止网络，并阻止读取用户目录内旧策略/实验文件，数值运行时路径除外。这是本实验的访问控制，不宣称通用恶意代码安全证明。
4. 评估器：物体真值只用于独立评分和本地证据文件，**不会作为 RPC 返回，也不会传给下一轮模型**。`trace.json`、完整 `result.json` 与给模型的简化 `actor_feedback.json` 分开。
5. 原三层塔 API 要求策略主动调用中间稳定性检查。本实验改成私有监视器自动观察蓝/红两层连续稳定 2 秒，约 50 ms 采样且检查 3 mm 漂移；策略不可查询该结果。最终仍调用原结构检查器检查完整三层稳定 5 秒，再调用原评分器。稳定性阈值没有为候选放宽，但中间检查的触发方式已改变。

视觉关闭对照将策略收到的 RGB 清零、深度置 NaN，策略报告桌面深度不足并停止，抓取动作数为零。这支持策略依赖视觉；单独一个对照不能证明所有信息隔离，需结合源代码、RPC、模型输入与 OS 边界审计。自动审计结果见 `audit/verification.json`，边界测试见 `tests/test_vision_boundary.py`。

## 4. 在这台 Mac 上复跑冻结策略

使用当前工作区及其 lock 文件。新 clone 上游不会自动包含本次新增脚本。

```bash
cd /path/to/aspire_so100
unset MUJOCO_GL
uv sync --frozen

# 输出目录必须不存在；这里会实际重新执行物理仿真
uv run python scripts/run_vision_trial.py \
  --candidate policies/stack_three_blocks_vision.py \
  --seed 91 --output outputs/my_vision_demo

# 根据刚保存的物理轨迹生成完整录像；不会重新执行策略
uv run python scripts/render_vision_trial.py \
  --trial outputs/my_vision_demo --speed 1 --fps 20

open outputs/my_vision_demo/demo.mp4
```

`result.json` 查看 success 与候选哈希；`camera_*.npz` 是实际传给策略的 RGB-D/标定数据；`api_calls.json` 是动作与传感器调用；`rollout.npz` 保留完整物理轨迹。策略停止后评估器仍会推进物理时间，因此录像长度比 `policy_sim_seconds` 更长。

这个视觉策略使用新的受限 SDK，**不能直接传给旧 `view_scene.py --candidate`**，旧接口不提供同样的 `camera()`/`proprioception()`。

## 5. 真正重新从空技能库学习

需要本机 `codex` 已登录且账户可调用 `gpt-6-astra`；不需要在文档中填写密钥。初始化只产生初始图像和实验协议，不加载已成功的视觉策略。

```bash
uv run python scripts/init_vision_campaign.py \
  --root outputs/my_new_vision_learning

uv run python -u scripts/run_vision_campaign.py \
  --root outputs/my_new_vision_learning \
  --model gpt-6-astra --rounds 0
```

**`--rounds 0` 表示不限制学习轮数，直到同一候选在 81/82/83 达到 3/3 才正常结束。** 每次执行结束立即录制，失败也录制，然后才进入下一次尝试。每轮模型调用有 300 秒超时，每次策略有 120 秒墙钟/600 次 RPC 上限；模型服务、隔离审计或渲染发生基础设施错误时会报错停止，避免悄悄漏掉录像。可 Ctrl+C 停止，已有证据保留。模型采样不保证新一次学习也恰好两轮成功。

冻结策略生成于新目录下 `best_policy.py`。之后用上节命令分别跑 seed 91、92，并各自渲染；验证结果不得回流用于调参。需要续跑已有完整候选时使用 `--start-round N`，程序复用已保存的结果和录像，不覆盖它们。若提案目录只写了一半，先检查错误，再使用新实验目录，不能将不完整提案当成功恢复。
