SENSORS
api.camera(view='side') gives rgb uint8[240,320,3], depth_m, valid_depth,
intrinsics 3x3, camera_to_world 4x4, time. Depth is optical-axis z in metres:
world = R @ (inv(K) @ [u,v,1] * depth[v,u]) + t.
Camera axes right/down/forward. api.camera(view='wrist') gives RGB/calibration,
but no depth. api.proprioception() gives five joint_angles, tool_position world
XYZ, tool_rotation 3x3, time. These are robot kinematics, not object poses.

MOTION
api.plan_tool(position, orientation=None): CPU robot-only IK preview; returns
joint_angles, tool_position, tool_rotation, position_error. This does not move
the robot or check object/table collisions. Orientation is a SOFT preference:
the 5-DOF robot cannot achieve every 6-DOF target. Check the planned pose.
Default orientation is [[0,0,1],[1,0,0],[0,1,0]]; local +Y then points upward
and the fingers extend downward along local -Y. Yaw alternatives are allowed.
api.move_joints(five_angles,seconds=1.5): smooth interpolation with limits
[-1.92,1.92],[-3.32,.174],[-.174,3.14],[-1.66,1.66],[-2.79,2.79].
api.move_tool(position,seconds=1.5,orientation=None): IK followed by joint motion;
raises if the planned position error exceeds 5 mm. Prefer previews near objects.
api.gripper(angle,seconds=.6): [-.174,1.75]; larger opens; .8 open, -.174 close.
api.wait(seconds): advance physics, 0..10 s. api.note(text): diagnostic log only.

ROBOT CALIBRATION (NOT OBJECT GROUND TRUTH)
This campaign uses robot_gravity_ff_v1: robot-model gravity feedforward through
the existing position actuators and original force limits. No objects are welded
or teleported. Payload/contact errors and finite settling time still exist.
Check IK approximation error separately from actual-versus-planned tracking.
Do not bypass a large tracking residual: it may indicate a table collision.
The tool marker is NOT the fingertip center. In the fixed-jaw frame it is at
(-.020,-.085,0); the lowest fixed finger pad extends to y=-.1064. Thus for an
upright gripper its lowest pad is about 21.4 mm BELOW the tool marker. Targeting
the marker at half the nut's height caused a finger/table collision previously.
Choose tool height using measured nut top and robot finger geometry, maintain
table clearance, and approach in small checked steps. Sensor-only infrastructure
checks found a marker roughly 7 mm ABOVE measured nut top can permit a pickup;
this is a starting hypothesis, not guaranteed success at every position/orientation.
Close only after a reachable, table-clearing approach. Inspect images after lift;
seeing the tool rise is not evidence that the nut rose with it.
